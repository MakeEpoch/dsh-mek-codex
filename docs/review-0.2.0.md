# 0.2.0 代码审查与验证

日期：2026-11-01（Asia/Shanghai）。审查对象：原 dsh-codex-panel 0.1.0。

## 审查结论

原来的 Host / Client 两端分离方向合理，使用 app-server 延续 Codex 原始会话也符合插件定位。问题主要在命名、实现职责集中，以及发送和审批的边界行为；不需要另建会话数据库或改写 DSH 布局。

原包名缺少 MakeEpoch 的 `mek` 命名空间，`panel` 只描述界面形式，不能概括运行时、会话和审批能力。因此改为 `dsh-mek-codex`，版本统一为 `0.2.0`。内部 `codex-panel` 兼容标识有意保留。

## 已纠正的问题

| 级别 | 原问题 | 本版处理 |
| --- | --- | --- |
| P1 | 超时/断线找不到 decline/cancel 时取首项，可能自动批准 | 只自动拒绝；没有安全拒绝项时返回协议错误 |
| P1 | 状态写入失败仍发消息，重启后可能丢失不确定状态 | 发送前持久化失败即阻止 dispatch；损坏状态文件保持 unsafe |
| P1 | 同一线程并发发送、早到或其他轮次终态可能误解锁 | 每线程发送互斥；只用匹配 ID 的终态解锁；覆盖早到竞态 |
| P2 | 刷新核对只读取缓存，无法从落盘轮次恢复 | 按精确 turn ID 读取终态；无 ID 不推断、不自动重发 |
| P2 | 刷新后忽略 pendingApprovals，事件游标归零/重置漏历史 | 恢复待审批快照与当前 ownership；处理初始与重置游标 |
| P2 | 多线程共用单个 live 对象，交错事件覆盖流式内容 | 按 threadId 分别保存流式状态 |
| P2 | 结构化审批允许仅传顶层标签 | 必须携带服务端提供的完整决定对象 |
| P2 | 生命周期启动、重启、卸载可交错 | 串行进程生命周期，避免旧进程退出回调覆盖新状态 |
| P2 | 业务 handler 查表可命中 Object.prototype 方法 | 仅派发自有方法 |
| 维护性 | 两个文件共 2,946 行，混合进程、RPC、状态、组件和样式 | 拆成 host/client/shared；增加构建、锁文件和 CI |
| 维护性 | 包 0.1.0 与握手 0.4.0 不一致，README 含过期本机路径和阶段声明 | 统一版本，重新编写安装迁移与证据说明 |

## 仍保留的边界

- 其他客户端的真实占用状态不由本插件推断；writer 的释放仍依赖退出 app-server。
- 不支持的权限请求、问答及 MCP 表单会明确返回错误，不伪装成通用 decision 审批。
- 无确定 turn ID 的发送超时继续阻止重发，需要人工核实；核对最多读取 500 轮。
- 差异正文尚未渲染；状态和上传文件需要按私人数据管理。

协议参考：[OpenAI Codex App Server](https://developers.openai.com/codex/app-server/)。本版还使用本机 CLI 生成的实验协议 JSON Schema 检查调用字段。

交互依据、状态路径和实现取舍见 [Codex 交互分析与插件改造](interaction-design.md)。
