# 列表缓存与后台更新

0.2.3 首次加载成功后，将默认未归档列表的前 100 条聊天及项目导航写入 localStorage。下次打开面板或刷新页面时，同步读出缓存，立即显示标题及项目分组；随后等待连接并请求最新列表，成功后原位替换并更新缓存。首次使用、缓存过期或缓存不可用时仍需等待网络。

后台更新保持列表组件、选中聊天和已有分组的展开状态。返回的首页是权威列表，已经删除、归档或移出首页的聊天会从该页移除，避免不断合并旧缓存导致脏数据。历史分页仍使用服务端新返回的游标，旧缓存不携带分页游标。

更新失败保留可见列表，显示更新失败和重试入口。搜索、目录和归档筛选使用实时请求，结果不写入默认缓存；来源筛选在当前列表上进行。相同请求正在执行时复用它，分页串行执行，筛选切换和组件卸载会取消旧请求并屏蔽迟到响应。每次打开、连接恢复或用户点击刷新时均拉取最新首页。

缓存键按 DSH 页面 origin（含端口）和挂载路径隔离，不包含登录 token。当前单用户 DSH 服务以不同 origin/挂载区分部署；缓存不是账号授权来源。只允许保存列表标题、执行目录、更新时间、来源及项目/分区归属等导航元数据，不保存消息正文、预览、图片、审批、运行状态或线程写权限。点开缓存聊天后仍从服务端读取当前详情与接入状态。

缓存使用版本标识，最多保存 100 条列表记录，7 天后失效，并限制序列化长度。JSON 损坏、版本不匹配、过期、localStorage 被禁用或额度不足都不会阻止正常加载。

同时移除侧栏 Codex 标题右侧的收起图标和对话标题前的文件夹图标；对话区的侧栏切换按钮和手机遮罩仍可控制侧栏。

回归覆盖缓存先于健康检查显示、后台原位替换、失败保留与重试、旧聊天移除、请求去重、分页取消、筛选响应竞态、卸载取消、缓存内容白名单、过期与禁用降级，以及 React 18 下完整发行 bundle 的渲染。组件与 bundle 回归使用模拟接口；它们不代表已完成登录后的 DSH 页面验收，也不证明服务端请求耗时降低。
