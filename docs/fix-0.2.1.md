# 0.2.1：React 兼容与项目导航修复

日期：2026-11-01。

## 打开聊天报 React #31

0.2.0 的开发预览和依赖环境使用 React 19，构建还把 React 19 的 JSX runtime 打进了浏览器包。真实 DSH 的前端资产使用 React 18.3.1；聊天 Markdown 返回的 React 19 元素无法被 React 18 渲染器识别，打开聊天因此崩溃。0.2.0 的模拟预览通过不代表真实 DSH 的兼容性已经验收。

0.2.1 将 JSX 调用统一适配到 DSH 注入的 `React.createElement`，不捆绑另一版本的 JSX 元素实现。测试环境对齐 React/ReactDOM 18.3.1，并增加加载完整生成 bundle、注册 DSH main slot、打开 Markdown 聊天的回归。虚拟历史测量也改成 effect 管理 ResizeObserver，避免依赖 React 19 的 ref 清理返回值。

## 项目不等于工作目录

Codex 当前有三个独立概念：

1. 注册项目：有稳定 ID、用户命名、一个或多个根目录，以及导航位置。
2. 聊天归属：聊天可以显式属于项目、分区、置顶，或明确没有项目。历史桌面归属可能尚未迁入 app-server。
3. 执行目录：`cwd` 描述聊天执行时所在目录，不能单独证明项目归属。

同一个目录可以属于两个项目；同一个项目可以有多个根目录。临时 sandbox、独立聊天的输出目录及历史 cwd 都不能自动成为项目。

0.2.0 直接按 cwd 建文件夹，既漏掉用户的项目名、分区与置顶，也把临时目录显示成项目。0.2.1 改为：

- 优先通过 `project/list` 读取原生项目，通过 `threadSection/list` 读取分区。
- 只读兼容桌面状态中的项目 ID 映射、明确聊天归属、明确无项目标记、项目排序、置顶和自定义分区。
- 聊天原生 `projectId` 优先；没有原生归属时读取历史明确归属；无证据时保留未知，不用路径或相似名称推断。
- 置顶、用户分区、普通项目分别展示；无明确注册项目归属的聊天集中到「其他聊天」，默认折叠并继续可搜索。
- 新聊天可显式选择原生项目，再选择执行目录；不通过修改桌面状态文件伪造归属。
- 不修改、迁移、删除、归档原始项目或聊天数据；不合并多账户中无法确认的分区布局。
- 列表按页加载，计数只代表已加载聊天；空项目在历史未加载完时不被宣称为没有聊天，可继续加载历史。

## 验证边界

新增生成 bundle 的 React 18 聊天渲染、ResizeObserver 清理、共享根目录下不同项目、无项目、未知项目、置顶、自定义分区、项目删除、只读缓存与搜索空结果等回归。

使用本机 app-server 与桌面导航元数据进行了只读验证，没有发送模型消息或写入项目数据。用户选择本次只完成修复和安装，因此本版不声称完成真实登录页面验收。远端 CI 和安装回执分别记录发布检查与实际安装结果。
