# Codex 交互分析与插件改造

依据：用户于 2026-11-01 提供的 Codex 截图、插件现有实现、OpenAI 官方应用与 app-server 文档。本文件区分截图中可见的事实、基于事实的设计判断，以及本插件实际实现。

## 1. 截图中的信息层级

左侧是长期工作空间：顶部新聊天与搜索，下面按区段和项目组织聊天。当前聊天有低对比度选中背景，部分聊天右侧有状态标记。项目与聊天上下级关系比时间和来源信息更突出。

中间是连续阅读空间。顶部只保留当前聊天标题和少量入口；正文保持较窄行宽并居中。用户能连续阅读助手说明，而不用穿过大量独立的工具卡片。执行记录使用摘要与折叠层次，长执行组有自己的展开区域。

底部输入框维持稳定位置。附件入口位于左侧，模型与推理档靠近右侧，当前执行的停止入口是最明确的实心按钮。输入区没有被多个同等权重的管理按钮挤占。

截图未打开顶部菜单、模型菜单或审批界面，因此不能从截图断言其中的完整选项、快捷键或权限策略。本插件的这些行为由自己的协议能力和数据安全约束决定。

## 2. 对现有插件的判断

| 场景 | 旧交互问题 | 改造后的交互 |
| --- | --- | --- |
| 找到聊天 | 来源、时间、ownership 和全套筛选长期占位 | 项目与聊天标题优先；搜索按需展开；目录/来源/归档筛选收进菜单 |
| 看当前上下文 | 顶部同时显示标题、完整 ID、目录、轮次、状态和所有操作 | 顶部常驻聊天标题与项目；技术信息收进会话详情 |
| 阅读助手回复 | 所有条目作为同级块，Markdown 直接显示为文本 | 用户消息和助手回复构成主对话流；支持段落、列表、代码块、表格和链接 |
| 查看执行过程 | 命令、思考和正文争夺注意力 | 相邻工具条目合并为执行组；组内每次操作可再次展开；思考摘要单独折叠 |
| 继续协作 | 发送、排队、中断、模型设置等控件散落 | 底部统一输入区；空闲发送、运行补充、明确停止；排队在发送选项内 |
| 切换聊天 | 组件重建后本地草稿可能丢失 | 父级按 threadId 保存本次页面会话中的文本与图片附件 |
| 阅读旧内容 | 实时输出可能干扰滚动 | 用户在底部时跟随；上滚后保留位置，提供回到最新消息 |
| 审批与异常 | 容易与普通工具信息混淆 | 审批区与普通执行折叠分开；不确定发送在输入区附近持续提示并阻止重发 |
| 新建聊天 | 原生 prompt 缺少项目上下文 | 应用内目录选择对话框，可复用已知项目；创建成功后直接选中新的原生线程 |
| 手机/窄窗口 | 上下分栏持续侵占聊天区域 | 项目导航改为侧栏抽屉，选择聊天后自动关闭 |

## 3. 主要用户路径

### 浏览并继续既有聊天

打开 Codex 插件 → 展开项目 → 选择聊天 → 查看历史 → 点击「继续此聊天」→ 接入原线程 → 底部输入区可用。浏览不会触发隐式 resume。

普通重命名、归档、删除和释放会话从右上会话操作菜单进入。运行时的重新连接和全部释放位于左下连接菜单，避免与单个聊天操作混淆。

### 创建聊天

点击新聊天 → 选择本机工作目录 → 创建 → 确认 app-server 返回的原生线程 → 选中该聊天并展示输入区。目录必须为绝对路径。创建失败保留表单并显示原因。

### 执行中补充要求

执行中仍可输入文本；Enter 或「发送补充」调用 steer；更多发送选项可排队。实心停止按钮只发中断请求，不伪装成直接结束成功。Enter 的中文输入法组词过程不触发发送，Shift+Enter 换行。

### 批准或拒绝

待审批请求显示在当前聊天输入区附近，含命令/文件、目录、原因及服务端提供的可选决定；审批不会被普通执行折叠隐藏。其他聊天有待审批时，项目导航出现入口。

审批只在用户明确点击后批准。超时、断线和不支持的请求按审查说明拒绝或返回明确错误。输入框中的「人工审批」说明本插件的实际行为；没有复制截图里的自动审批开关。

### 断线与发送未知

断线保留本次页面会话中的草稿。发送结果未知时停用普通发送，提供恢复草稿与刷新核对；核对只接受精确轮次 ID 的落盘终态。没有轮次 ID 时继续保留未知状态，不根据相似文本猜测成功。

## 4. 交互实现与结构

- `panel.js` 负责选择状态、项目列表、响应式导航、新聊天及草稿索引。
- `conversation.js` 负责当前聊天的历史、接入状态、详情、模型表单和输入连接。
- `components/composer.js` 集中输入、图片选择/粘贴、发送、补充、停止、模型入口及排队菜单。
- `components/turns.js` 负责对话与执行分层、历史虚拟滚动及回到底部。
- `components/markdown.js` 使用安全 Markdown 渲染，不执行内容中的原始 HTML。
- `components/dialog.js` 提供 Escape 关闭、焦点归还和 Tab 焦点约束。
- 流式状态按线程分开保存；工具终态和线程终态继续使用 Host 的权威事件与安全状态。

## 5. 范围与证据边界

实现的是 DSH 中的 Codex 会话协作界面。截图中的 Codex 全局工作空间、其他产品入口、语音、自动审批、自动化、分支/worktree 和未知的右侧面板功能没有被做成无后端支撑的按钮。

项目分组由 Codex 返回的 cwd 派生；不因此声称实现了 Codex 桌面的分区或置顶同步。草稿在当前插件页面会话中保留，刷新或关闭页面后的持久化恢复不是本版保证。

浏览器预览使用虚构数据并加载实际发行构建，不等同于 DSH 安装验收。真实 app-server 的只读冒烟与自动回归结果另见审查记录。
